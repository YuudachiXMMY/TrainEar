# J-Rock 练耳训练器 · 现状 PRD

> 本文档基于当前代码库（`main` 分支，2026-11-22）反向整理，目的是为**界面改版与 UX flow 重设计**提供完整现状基线，而非新功能规格。所有描述均对应已实现、可运行的功能。

---

## 1. 产品定位

Bass 手专用的分阶段听力训练 Web App，配套《Bassline 学习方法论与练习路线》第三部分（阶段 0–3）。题库取材 J-Pop / J-Rock 高频套路（王道、小室、卡农、Axis、悲怆循环、下行线、丸サ、平行调借用）。纯前端 + 轻量 Node/Express 后端，支持离线单机使用（`file://` 直接打开）和联网账号云同步两种模式。

## 2. 功能清单

### 2.1 练耳主线（阶段 0–3）
| 模块 | 档数 | 内容 |
|---|---|---|
| 阶段 0 热身 | — | drone 加唱级数音型，数字跟随高亮 |
| 阶段 1 根音追踪 | 4 档 | 级数听辨（三八度目标音、5/6m 加权、1 级防背音高）、根音走向、终止式 |
| 阶段 2 性质听辨 | 4 档 | 三度对比、三和弦、属七、七和弦家族；答错可 A/B 对比听 |
| 阶段 3 套路整体识别 | 5 档 | 套路池递增、套路变奏（随机调+变奏伴奏）、调外和弦侦测（副属/借用4m/b6b7，带全调内版 A/B 对比） |

### 2.2 指板三件套
| 模块 | 档数 | 内容 |
|---|---|---|
| 指板 1 · 音名地形 | 4 档 | 低/中高把位找音名（先自然音，近20题85%解锁升降音）、看位置说音名（12选1）、找全同名音 |
| 指板 2 · 级数定位 | 5 档 | 报级数找根音、看位置认级数、和弦音形状（级数决定 M7/m7/属七/半减七）、套路根音连弹、换调平移 |
| 指板 3 · 模进训练 | 5 阶段 | 三度模进、三和弦琶音模进、四音音型、下行模进、七和弦+换调 |

指板模块支持 4/5 弦调弦设置（默认 5 弦 BEADG），含预设与逐弦自定义，以 1 级为原点讲形状，跨非四度弦对时提示挪品。

### 2.3 乐理课（5 门，27 课 + 33 档练习）
每门课 = 图文讲解页（可点指板/播放示例）+ 分档练习，答错可一键回看讲解。
1. 基础乐理（6课/6档）
2. 调内和声与级数（5课/7档）
3. 套路与和声进阶（5课/6档）
4. 低音线与节奏（5课/6档）
5. 和弦与指板（6课/8档）

拼写引擎按「每个字母用一次」规则拼音阶/音程/和弦，12 大调随机出题。

### 2.4 音色系统
默认采样电贝斯（Karoryfer CC0 真实录音，逐半音采样+双 round robin），另有 KS 建模贝斯、减法合成贝斯、clean 电吉他、EP 键盘，以及自定义采样音源（上传单音、自动识别音名、就近变调铺满全音域）。

### 2.5 账号与云同步
注册（邮箱验证码）、密码或验证码登录、进度与音源存服务器，换设备续练。**同步策略为整份 JSON 覆盖式存取（last-write-wins），无字段级合并** —— 多端同时练习时后写入覆盖先写入，这是现状限制而非 bug。

### 2.6 进度与统计
过关线：每档近 20 题正确率 90%。进度页含每日题量、连续天数、累计题数、总正确率、逐模式逐档进度条、最常混淆 Top 6（纯文字列表）、数据导出/导入（文本框）。

### 2.7 后端 API 面
- `auth`: register / verify / login / request-code / login-code / logout / me
- `progress`: GET / PUT（整份覆盖）
- `samples`: 列表 / 上传 / 删除 / 取文件

## 3. 现有界面结构（改版基线）

### 3.1 路由机制
单一状态机，核心变量 `S.screen`（枚举：`home / mode / quiz / lesson / warmup / progress / auth / sources`）。**无 hash / history，`render()` 按 `switch(S.screen)` 整页重绘（innerHTML 替换），无组件化、无前进后退浏览器支持。**

### 3.2 导航层级（3 层深度）
```
home（首页）
├─ 6 个练耳/指板模式卡 + 5 门乐理课卡 + 热身/进度/音源/账号入口
└─ mode（二级：某模式下的档位列表）
   └─ quiz（三级：具体答题页）
   乐理课平行体系：mode → 课程列表 → lesson（讲解页）→「去练」→ quiz
```
返回靠统一 `goBack()`：quiz/lesson 回 mode，其余回 home。特殊状态 `lessonFromQuiz` 记录「答错→回看讲解」是**整屏跳转**而非弹层，返回会跳回原 quiz 而非 mode —— 这是一个容易让用户迷失层级的隐藏状态分支，改版时值得重点关注。

### 3.3 答题页交互骨架（三套实现，结构统一但未组件化）
`renderQuiz` / `thRenderQuiz` / `renderFretQuiz` 分别服务于练耳、乐理课、指板三类题型，HTML 结构和交互约定高度一致：
```
顶部档位名 + 统计（近20题正确率/连对/本档计数）
→ 播放区（大播放按钮 + 节拍点 + 文字提示 + 再听/慢速再听）
→ 选项按钮组（correct/wrong/dim 状态类）
→ 反馈卡（标题 + 详解 + 回看讲解/AB对比按钮 + 下一题）
→ 底部键盘提示（数字选答案、空格重听、回车下一题、Esc返回）
```
三份渲染函数并行维护，视觉统一但有重复代码 —— 改版若要统一体验，这是天然的组件化切入点。

### 3.4 设置入口（分散在 4+ 处，无统一设置中心）
- 首页可折叠 `<details>`（调、随机调、BPM、音色、音量）
- 答题页内重复的音色/随机/高八度小字选项
- 指板类模式在 `mode` 页单独一块调弦设置
- 账号登录/注册、自定义音源管理各是独立全屏页

### 3.5 进度页
4 个数据卡 + 逐模式逐档进度条列表 + 纯文字 Top 6 混淆统计 + 导出/导入文本框。**无时间趋势图、无可视化图表。**

### 3.6 视觉系统现状
`app.css` 已有设计系统雏形：深色主题变量（`--page/--surface/--ink/--hairline`）、统一圆角 `--radius:14px`、内容最大宽 `--maxw:780px`、**11 个模块各自的强调色变量**（`--accent-*`，模式卡/反馈动态着色）。但缺间距比例尺、字号阶梯、组件变体系统；答题页信息密度偏高（同屏塞统计+播放+选项+反馈+键盘提示）。

## 4. 改版时值得关注的现状问题（非 bug，是设计债）

1. **层级迷失风险**：`lessonFromQuiz` 这类隐藏返回状态，用户心智模型里的"返回"和实际跳转目标可能不一致。
2. **设置分散**：四处设置入口增加认知负担，统一设置中心是可考虑的方向。
3. **进度页纯文字化**：缺可视化趋势，想感知"最近是否在进步"较难。
4. **三套答题渲染并行**：视觉已统一但代码未统一，若改版想做"交互模式升级"（如手势、动画过渡），三处都要改。
5. **无浏览器历史/深链接**：无法用浏览器前进后退，也无法分享某个具体档位的链接。
6. **整页重绘**：每次 `render()` 都是整页 innerHTML 替换，过渡动画/状态保留（如播放中切页）天然受限。
7. **信息密度**：答题页同屏信息较多，移动端窄屏下尤其紧凑。

## 5. 技术栈与运行方式（供改版参考边界）

- 前端：纯 Vanilla JS（无框架），多文件职责拆分（`theory.js`/`fret.js`/`drills.js`/`th-engine.js` 等 + `audio.js` Web Audio 引擎）
- 后端：Express + better-sqlite3，`server/` 下 auth/progress/samples 三个路由模块
- 离线模式：直接双击 `public/index.html` 可用，训练功能完整，仅无账号/云同步/自定义音源
- 测试：Playwright 端到端（`tests/e2e.mjs`）+ 乐理课不变式与界面冒烟（`tests/theory.mjs`）
